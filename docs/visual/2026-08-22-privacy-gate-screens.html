← → keys

Build in this order

OrderScreensWhy
1stS1 → S4 → S5 Drop, approve, confirm. This alone is a demo, even with the detection faked.
2ndS3 · E1 Swap fake spans for real Gemma plus the pattern-matching fallback.
3rdS6 → S7 Wire the cloud half. Easiest part, starter/ has working examples.
4thS8 · E3 Receipt and the cached fallback. Both cheap, both protect the demo.
if timeS2 · E2 Polish. The loading state and the empty case can be skipped.
Build S5 before it works. Hard-code the redacted output if you have to. It is the screen the whole pitch rests on, and once it exists everything else has an obvious target. A demo with S1, S4 and S5 real and the rest faked will score better than a complete pipeline with no confirmation screen.

What that costs: you will throw away the hard-coded version around 15:30. That is fine. Twenty minutes of rework buys you a demo that exists at all.
