What your prompt missed

These get injected into every agent prompt and into the cross-model prompt file. Each one changes which ideas survive.

  1. Build window is ~4h net, not 3h — 12:30→17:30 minus a 1h lunch. Correct target: 3h build + 45min demo polish/deploy + 15min submission buffer. Ideas sized for a literal 3h with no polish time lose on presentation. derived
  2. Track unknown until 12:15. Score every idea for re-skin cost against plausible tracks (agents / on-device / accessibility / productivity / creative / safety).
  3. The rubric is roughly 25–50% technical execution, 20–30% innovation, 10–20% demo, with an explicit "did you use Gemini/Gemma meaningfully" line in every comparable Google rubric. A build that could have used any LLM forfeits a whole category. derived: docs/08
  4. Judges perceive ~90 seconds. Demo weight is formally small and practically decisive. Every idea needs a nameable wow moment that fires inside 90s. derived: docs/08 §3
  5. Public link, no login. A localhost demo scores as if broken. Every idea must be deployable to a public URL inside the window. derived: docs/08 §5
  6. Judge-triggerable interactivity beats a canned flow — an idea where a judge supplies the input ("say any word", "give it any receipt") reads as real, not rehearsed.
  7. Name a newly-shipped feature out loud: Gemini 3.7 Flash agentic tool-use, Gemma 4 on-device multimodal, Interactions API, computer-use preview, ADK/A2A. Old-API builds read as last year's project.
  8. Free tier is 15 RPM. A demo that fans out parallel calls will rate-limit on stage. Idea must survive a throttle, or hold a recorded fallback. derived: docs/07
  9. Venue wifi is a real failure mode. On-device Gemma 4 fallback is both insurance and a scoring feature — it maps straight onto Ian Ballantyne's keynote.
  10. "Nobody built it" needs evidence, not vibes. Each idea gets a prior-art sweep — Devpost, GitHub, Product Hunt, App Store, Play Store — naming the closest existing thing and the specific delta. Unsearched = rejected.
  11. "Useful to the majority" needs a frequency number. How many times per week does an ordinary adult hit this problem, with a source. A great tool used twice a year loses to a mediocre one used daily.
  12. Antigravity is a build tool, not a product surface. Using it is a process story ("we shipped this in 3h with Antigravity"), not a product feature. Don't let an idea's novelty rest on it. assumed — confirm at briefing
  13. Third-party OAuth is a trap. Anything needing Gmail/bank/calendar consent screens burns an hour and breaks on a judge's machine. Prefer paste-in, upload, camera, or mic input.
  14. One feature, one golden path. Multiple half-finished features lose to one polished workflow — the single most repeated line in every judging writeup. derived: docs/08 §5
  15. The one quotable number. Each idea must produce a before/after a judge can repeat unaided: "cut a 45-minute task to 60 seconds."
  16. Speaker bias is a scoring input. Amit Vadi = frontier agents; Ian Ballantyne = on-device Gemma. An idea that touches both scores twice. derived: docs/00, docs/08 §4
  17. Accessibility and offline framing win disproportionately with Google judges — the Gemma 3n precedent won in two separate tracks. derived: docs/08 §2
  18. No medical, legal, or financial advice claims. Judges poke exactly there, and a hedge-laden demo kills the wow.
  19. Anti-template filter. Auto-reject: "AI assistant for X", chat-wrapper-over-documents, generic RAG, another meeting summariser. Judges say the standouts depart furthest from the template.
  20. Team size and skills are unstated in your prompt. Assumed: small team, Python + web, using the starter kit already in starter/. Ideas requiring native mobile, custom training, or a fine-tune are out on time alone. assumed

What you get, in plain words

The portfolio

Six ideas, ranked. Each one fits on a card: the problem in one sentence, the thing a judge sees in 90 seconds, which Google feature it names out loud, the closest product that already exists and why this is not that, the file list to build it, and what breaks first.

The track map

A row per plausible track (agents / on-device / accessibility / productivity / creative / safety) showing which of the six ideas fits it and what you'd change. At 12:16 you read one row and start.

Three independent opinions

Fable 5's list and GPT-5.6's list stay separate from mine, side by side, so you can see where three different models independently converged — convergence is the strongest signal that an idea is real, divergence is where the un-built ideas hide.

An adversarial verdict

A fresh Opus 4.8 with no stake in the work marks every "nobody built this" and every "3 hours" as SUPPORTED, UNSUPPORTED or FALSE, with a link or a file for each. You will know which ideas are real before you bet four hours on one.
